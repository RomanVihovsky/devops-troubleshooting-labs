# Encryption at rest rollout took the API server down
**INC-2851** · P1 · Reporter: security

For the audit we enabled encryption at rest for Secrets on `k8s-cp1`: an EncryptionConfiguration with an `aescbc` key
in `/etc/kubernetes/enc/enc.yaml` and `--encryption-provider-config` on the API server. The key was generated by
hand. Since then the API server doesn't come up. Finish the job: the API must run with Secrets encrypted with
`aescbc` - and the auditor will check that **existing** Secrets (like `payments/stripe-key`) are encrypted too, not
just new ones.

**Test**: the API answers and all nodes are Ready; the API server uses the encryption config with `aescbc` as the
first provider; a new Secret and the pre-existing `payments/stripe-key` are stored as `k8s:enc:aescbc:v1:` in etcd.
